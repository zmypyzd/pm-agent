## Why 0 PRs is the correct outcome here

With no git remote configured in the dogfood repo, every `gh pr create`
exits non-zero, so every `github.open_pr`/`auto_merge` call returns
`PRResult(action="failed", number=0)`. Pre-R4 the loop:

1. called `record_pr(..., gh_number=0)` regardless,
2. the first row inserted (UNIQUE doesn't fire for a single number=0),
3. proceeded to `update_finding(done)` + `findings_fixed += 1` —
   wrongly counting a failed PR as a fix.

The second failed PR per cycle then collided on UNIQUE and crashed the
finding. So D1's "1 fixed" was *the first-per-cycle failure flipped to
fixed*, not a real fix. R4-1 now correctly routes
`pr.action == "failed"` → `update_finding(failed)` → `continue`, with
the persistence layer refusing `gh_number <= 0` as defense in depth.

Net: D2's 0 fixed is the **correct** count when no PRs can be opened.
